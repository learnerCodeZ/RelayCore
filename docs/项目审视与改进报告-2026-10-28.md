## 3. 已确认问题

### R1 / P1：非法控制台请求能使 Daemon 退出

位置：`src/daemon.mjs`，`POST /ui/action` 请求体解析和任务 ID 校验。

这些语句处于现有动作分支的 `try/catch` 之外；异步 HTTP 处理器抛出的异常没有统一出口。隔离子进程收到正文为 `{` 的 POST 后出现 `SyntaxError`，**退出码为 1**。服务退出会中断本地控制和正在运行的任务；重启可能转入恢复状态。

改进：统一捕获 HTTP 路由中的异常；将畸形 JSON、非法参数和过大请求转为明确的 HTTP 错误，按实际字节限制正文大小。测试应确认错误之后服务仍能处理正常请求。

### R2 / P1：同源基准来自不可信的 Host

位置：`src/daemon.mjs`，`localOrigin` 与 `browserSafe`。

原实现将请求中的 Host 拼接为允许的 Origin。隔离请求使用外部域名形式的 Host、同名 Origin 和 `same-origin` 元数据，**返回 200 并生成授权记录**。监听 `127.0.0.1` 只能限制网络地址，不能证明 HTTP Host 是可信本地地址。

已验证的是服务端接受上述请求；**没有完成真实浏览器 DNS 重绑定攻击验证**。实际利用还受浏览器、本地网络访问防护、DNS 和网络配置影响。不能据此声称用户机器已经被攻击，也不能继续宣称跨站请求在所有环境中“结构性不可能”。

改进：从真实监听端口建立明确的本地主机白名单；先校验 Host，Origin 必须与该已验证本地地址一致；继续拒绝跨站 Fetch 元数据。覆盖只读页面、控制台动作及 API，保留合法 `localhost` / `127.0.0.1` 用法。

### R3 / P2：模型执行成功，但账本没有记录

位置：`src/dsh.mjs` 的 `runDshReviewTask()`；`src/core.mjs` 的执行上下文和 `usageSummary()`。

记录方法是 `context.recordUsage`，组合执行器却检查并调用 `core.recordUsage`，后者没有导出。隔离假适配器提供 DSH、Codex 用量，任务到达 **COMPLETED，账本仍为 0 行**。因此旧文档“执行链真实记账、代码已确认正确”的结论不成立。

此外，现有映射将 DSH `used` 当输入 token，将 `size` 放到“上下文占用”列，会混淆上下文已用量、容量和单次输入/输出。缺失用量也不能显示为零费用。

改进：接通执行上下文；分别保存 token 计数和上下文占用/容量，明确未知字段；使已有数据库兼容升级。用实际组合执行器的假适配器测试确认两种用量落库与重开保留，不能只测记账方法本身。

### R4 / P2：记忆首次写入有目录创建竞态

位置：`src/core.mjs` 的 `memoryAppend()`。

函数同步写文件，却调用未等待的异步 `mkdir()`。在受控单工作线程繁忙的隔离进程中，首次写入稳定出现 **ENOENT**。普通测试通过只代表当时目录创建足够快。

改进：保持现有同步 API，使用同步目录创建，让目录准备与写入有确定顺序。增加线程池繁忙时首次写入及归档的回归。此修复不等于解决磁盘与数据库的整体事务一致性。
