## 边界与未做

- `/ui` 操作不带 Bearer，不验证 Windows 用户身份；其他可访问本地端口的进程或用户仍可能读取和操作，不能等同于 DPAPI 保护的 CLI。授权按钮目前仍同时同意未知费用和 E2 的 L3，需后续分离同意流程。
- 用量是**执行器返回的观测记录**，不保证每次调用均有记录，也不是金额硬上限。DSH 上下文不换算为 token 消耗；未知显示 `—`。历史行保留原字段并标记 `legacy-unclassified`，不猜测旧口径或补造漏记数据。
- 用户级后台启动（服务/计划任务）与自动升级管理**未实现**，以 README 手动启动方式替代——涉及系统配置的改动需用户明确决定。
- `logs/TASK-*.jsonl` 未实现：事件表已承担审计，避免重复存储。

旧版文档曾称“执行链真实记账、代码已确认正确”，但本轮隔离复现发现任务成功仍为零行：组合执行器错误地调用 `core.recordUsage`，实际方法属于执行上下文。这不是仅凭“当时数据库没表”就能排除的问题。详细证据和剩余改进见[项目报告](项目审视与改进报告-2026-10-28.md)。

## 2026-10-29 续：控制台身份验证与分项同意（审视报告第 8 节第 2、3 项）
