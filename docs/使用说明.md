# RelayCore 使用说明

更新时间：2026-10-28。适用对象：在 Windows 本机体验当前开发版本的用户。

## 1. 现在能做什么？

RelayCore 仍在开发和验收阶段，**可以在独立测试目录中试用，但不建议直接处理重要项目或生产数据**。默认启动只提供控制服务，不会自动调用模型或修改用户源文件。

已经实现的能力包括：通过 MCP 创建和查询任务、显式授权后派发、DSH 账户提案、独立 Codex 审查、查看候选结果、由用户明确操作整合及回滚。还有工作区副本、任务版本、暂停/恢复、本地控制台和用量记录。它们的存在不代表所有故障、安全和费用边界已验收。

已知证据与限制：

- 2026-10-28 完成本轮修复后，有时限的无模型自动测试记录为 **138/138 通过**；这是当时的测试结果，不保证未来修改后仍然通过。问题和改进顺序见[项目审视报告](项目审视与改进报告-2026-10-28.md)。
- 以前有一次隔离环境下的真实双模型提案、审查、整合和回滚成功记录。另一次真实在途暂停诊断在提取快照 ID 时失败，没有完成那次整合/回滚；探针提取逻辑已修复，但未重跑该真实链路。
- Phase 0 的完整安全准入仍未通过：候选副本不等于操作系统级沙箱，Windows 权限、网络、子进程和异常恢复尚未全面验证。
- 模型提示次数和时长上限不是金额硬上限。真实调用可能消耗 DSH、Codex 账户额度或产生费用；服务端计费与 `/usage` 记录不一定相同。
- `/usage` 中 DSH 的 `used/size` 是上下文占用/容量，不是单次输入/输出 tokens。`—` 表示未知；旧记录保留为 `legacy-unclassified`，不会猜测其计费含义，也不会补造以前漏记的用量。
- 控制台仅接受当前端口的 `127.0.0.1` / `localhost` 地址，但没有 Windows 用户身份认证；可访问该端口的其他进程或用户仍可能操作它。不要把本机访问限制理解为只有你能授权。

建议按顺序进行：**先无模型连接和草稿验收，再在专门的测试目录执行一次小任务；真实项目等安全与可靠性验证完成后再考虑使用。**

## 2. 先认识三个目录

以下路径是本机示例，换机器时需要调整。

| 目录 | 用途 |
| --- | --- |
| `D:\MYCODE\RelayCore` | RelayCore 程序和代码所在目录。 |
| `D:\MYCODE\RCtest` | 你已打开的 DSH 账户测试工作区；本指南沿用它作为 DSH 会话工作区，不复用其中原有对话。 |
| `D:\MYCODE\RelayCore-tryout` | 本指南创建的**新测试项目**，用于放一个无价值的样例文件和这次测试产生的任务数据。 |

执行任务时，`allowedPaths` 相对于 RelayCore 正在服务的**测试项目**，而不是 DSH 安装目录。即使 DSH 会话工作区是 `RCtest`，本例的目标源文件仍是 `RelayCore-tryout\message.txt`。候选副本位于测试项目的 `.RelayCore/` 下，**审查通过也不会自动写回源文件**。

## 3. 需要准备什么？

1. Windows、Node.js **24.15.0 或更新的 24.x 版本**，以及已安装依赖的 RelayCore。可在 PowerShell 输入 `node --version` 查看版本。首次安装依赖时，在 RelayCore 程序目录运行 `npm ci --include=optional --ignore-scripts`；这会访问依赖仓库并在项目内创建 `node_modules/`。
2. 要从 Codex 对话调用工具，需要本机可用的 Codex CLI / Desktop 和 RelayCore MCP 连接。本指南会使用独立测试连接，避免覆盖现有 `relaycore` 配置。
3. **无模型验收**不需要 DSH API Key、DSH 账户请求或 Codex Review 登录。
4. **真实模型试用**需要 DSH 已登录账户，以及单独可用的 Codex Review 登录。DSH 的登录不等于 Codex Review 已登录；账号和额度是否可用需要实际检查。账户模式不要求把 API Key 发到聊天。

不要在对话中发送 Key、授权链接、验证码、控制令牌或登录文件。`.RelayCore/`、`local/` 可能包含敏感数据，也不要直接打包公开分享。

## 4. 第一步：创建隔离测试项目

在 PowerShell 执行。以下命令会在 `D:\MYCODE` 创建新目录和一个样例文件；如果目录已经存在会直接停止，不覆盖已有内容。若路径存在，请换一个全新目录，并在下文所有位置使用同一新路径。

```powershell
$demoRoot = 'D:\MYCODE\RelayCore-tryout'
if (Test-Path -LiteralPath $demoRoot) {
  throw '测试目录已存在，请换一个全新目录；未覆盖任何文件。'
}
New-Item -ItemType Directory -Path $demoRoot -ErrorAction Stop | Out-Null
$demoFile = Join-Path $demoRoot 'message.txt'
[System.IO.File]::WriteAllText($demoFile, "pending`n", [System.Text.UTF8Encoding]::new($false))
Get-Content -LiteralPath $demoFile
```

预期输出 `pending`。这个测试目录包含与程序仓库**分开的**源文件和运行数据。不要把本例的相对路径误指向重要项目。

## 5. 第二步：无模型启动和查看

在**同一个 PowerShell 窗口**继续运行：

```powershell
Set-Location -LiteralPath 'D:\MYCODE\RelayCore'
$env:RELAYCORE_ROOT = 'D:\MYCODE\RelayCore-tryout'
$env:RELAYCORE_PORT = '18765'
Remove-Item Env:\RELAYCORE_EXECUTION -ErrorAction SilentlyContinue
Remove-Item Env:\RELAYCORE_TOKEN -ErrorAction SilentlyContinue
npm start
```

预期看到类似 `RelayCore control server on 127.0.0.1:18765; external execution disabled`。保持这个窗口打开。它只监听本机；第一次启动可能为**测试项目**生成控制令牌，保存在其 `.RelayCore/` 中。

保持启动窗口打开，在第二个 PowerShell 窗口运行以下命令获取控制台的一次性登录令牌。

```powershell
Set-Location -LiteralPath 'D:\MYCODE\RelayCore'
$env:RELAYCORE_ROOT = 'D:\MYCODE\RelayCore-tryout'
$env:RELAYCORE_PORT = '18765'
Remove-Item Env:\RELAYCORE_TOKEN -ErrorAction SilentlyContinue
node .\src\control.mjs ui-session
```

在浏览器打开 `http://127.0.0.1:18765/ui`，将输出中的 `sessionToken` 字段值粘贴到登录框，点击登录。令牌只能兑换一次，登录会话最长 8 小时，Daemon 重启后失效。令牌只用于本机登录，请妥善保管。登录后任务列表为空是正常现象，控制台提供查询和任务操作入口。

如果提示端口被占用，请选一个其他本机空闲端口，并在后续 MCP 与控制命令中同步修改。**不要为了试用停止来源不明的进程或直接删除旧锁。** 2026-10-28 本次检查时，项目原目录的 8765 无响应，但旧 `daemon.lock` 仍在，锁内历史 PID 51512 未找到；这是一次观察，不保证之后状态不变。本例使用不同项目根目录及端口，不需要清理原锁。

## 6. 第三步：连接 MCP 并创建草稿

以下命令会**修改当前 Windows 用户的 Codex MCP 配置**，新增一个名为 `relaycore-tryout` 的测试连接，不修改现有 `relaycore` 配置。先在另一个 PowerShell 窗口运行 `codex mcp list`；如果这个名字已经存在，请改用其他名字。`D:\Node_js\node.exe` 是本机示例，若不在该路径，先运行 `(Get-Command node).Source` 查看实际路径并替换。

```powershell
codex mcp add relaycore-tryout --env 'RELAYCORE_ROOT=D:\MYCODE\RelayCore-tryout' --env 'RELAYCORE_PORT=18765' -- 'D:\Node_js\node.exe' 'D:\MYCODE\RelayCore\src\mcp.mjs'
codex mcp list
```

这条配置不包含 Key 或控制令牌。Daemon 与 MCP 需要在**同一 Windows 用户**下运行，且都指向相同的测试项目与端口。新增连接后，如果当前 Codex 会话看不到它，先保存正在进行的工作，再按应用支持的方式重新加载 MCP 或重开应用；不要在其他任务运行时贸然重启。

在能使用 `relaycore-tryout` 的 Codex 对话中，发送以下内容，让它调用 `create_task` 并查询结果：

```text
请使用 relaycore-tryout 的 create_task 创建一个草稿：
title: RelayCore 测试任务
objective: 把 message.txt 的内容改为 ready 后接一个换行。
acceptance: 只允许改 message.txt，内容必须精确为 ready 和一个换行。
allowedPaths: ["message.txt"]
executionLimits: {"maxDurationSeconds": 600, "maxModelTurns": 2}

创建后调用 task_status 和 task_events，告诉我任务 ID 与状态。
这次只创建和查询草稿，不授权、不派发、不调用模型。
```

验收标准：获得形如 `TASK-...` 的 ID，状态为 `DRAFT`，事件中有 `task.created`。测试项目的 `message.txt` 仍为 `pending`。这一步**没有发送模型提示**。如果只是想验收连接，到这里即可结束；可以让 Codex 调用 `stop_task` 取消这个草稿。

原有 `relaycore` 连接如果只有五个旧工具，可能看不到 `dispatch_task`；不要仅凭注册清单认定实际调用成功。早期配置示例见 [MCP 手动连接](codex-mcp-manual-setup.md)，其中部分叙述是 2026-10-25 的历史状态；本指南的测试连接步骤以当前代码为准。

## 7. 可选：进行一次真实模型试用

只有在你理解可能花费和当前限制后才做这一步。使用独立样例，不提交真实代码、不放敏感数据。**一个任务最多允许两次 Bridge 模型提示、最长 600 秒**：通常是一次 DSH 提案和一次 Codex Review；排队时间也计入时限。适配器内部行为和实际账单不一定与提示次数一一对应，金额无法硬封顶。失败后先检查现场，不自动重试。

### 7.1 检查账号并切换测试服务

DSH 使用你自己的账户；确保 DSH 能使用 `D:\MYCODE\RCtest`，不必向 RelayCore 提供 DSH API Key。Codex Review 是另一份独立登录，在 RelayCore 程序目录、你自己的 PowerShell 中检查：

```powershell
Set-Location -LiteralPath 'D:\MYCODE\RelayCore'
node .\scripts\login-codex-review.mjs --status
```

如果输出 `{"authenticated":true}`，只说明该检查报告登录可用，不能保证模型或额度一定可用。如果报错或报告未登录，不要把登录文件内容发送出来。需要登录时可由你自己运行 `npm run login:review` 并在浏览器完成授权；该**登录动作**会为专用登录目录及已有凭据文件设置访问权限。不要用管理员身份替其他 Windows 用户登录。

关闭**第 5 节由你自己启动的测试服务窗口**（确认没有任务运行后，在该窗口按 `Ctrl+C`），然后在同一个窗口重新设置并启动。不要停止其他项目或不明来源的 Daemon：

```powershell
Set-Location -LiteralPath 'D:\MYCODE\RelayCore'
$env:RELAYCORE_ROOT = 'D:\MYCODE\RelayCore-tryout'
$env:RELAYCORE_PORT = '18765'
$env:RELAYCORE_EXECUTION = 'account'
$env:RELAYCORE_DSH_EXE = 'D:\DeepSeekHarness\DeepSeek Harness.exe'
$env:RELAYCORE_ACCOUNT_WORKSPACE = 'D:\MYCODE\RCtest'
$env:RELAYCORE_MAX_DURATION = '600'
$env:RELAYCORE_MAX_TURNS = '2'
Remove-Item Env:\RELAYCORE_TOKEN -ErrorAction SilentlyContinue
npm start
```

预期日志包含 `account execution enabled`。环境变量只作用于这个 PowerShell 窗口及其子进程；关闭窗口不会永久设置。你的网络若需要本地代理，应在启动窗口自行确认代理正常。仍然不要把密钥或令牌写入这些命令。

### 7.2 授权并派发

如果第 6 节已取消草稿，先按同样内容重新创建一个草稿。然后在**另一个 PowerShell 窗口**设置相同的测试项目和端口。把 `TASK-替换为实际任务ID` 换成第 6 节得到的完整任务 ID：

```powershell
Set-Location -LiteralPath 'D:\MYCODE\RelayCore'
$env:RELAYCORE_ROOT = 'D:\MYCODE\RelayCore-tryout'
$env:RELAYCORE_PORT = '18765'
Remove-Item Env:\RELAYCORE_TOKEN -ErrorAction SilentlyContinue
$taskId = 'TASK-替换为实际任务ID'
node .\src\control.mjs status $taskId
node .\src\control.mjs authorize $taskId 600 --allow-unknown-cost
node .\src\control.mjs dispatch $taskId
```

`authorize` 表示你接受该任务费用未知并授予一次性执行权限，`dispatch` 开始调度。默认任务风险等级为 E1。控制台授权需要分别勾选费用同意与 E2 的 L3 同意，两项默认均未勾选。对于 E2 任务，CLI 授权还须加 `--e2-approved`。MCP 可以派发已授权任务，本地 CLI 或已登录控制台负责授予授权。

在第二个窗口查询进度：

```powershell
node .\src\control.mjs status $taskId
node .\src\control.mjs events $taskId
```

`DRAFT` 是草稿，`QUEUED` 是排队，`RUNNING` 是执行中，`COMPLETED` 是审查通过并生成交接，**不等于已合并**。`RECOVERY_REQUIRED` 表示发生错误、超时、停止或其他未知情况，需要人工核对事件和现场；不要把它当成成功或自动重试。

可以使用 `node .\src\control.mjs pause $taskId` 暂停、`resume` 恢复或 `stop` 请求停止；但真实在途暂停后完整整合/回滚尚未重新验收，恢复也不会重置原有预算。停止本地任务不保证远端模型或其费用立刻停止。

### 7.3 查看候选，决定是否整合

仅当任务为 `COMPLETED` 时，先在本机查看交接与候选；不要把可能含敏感内容的文件发到公开对话：

```powershell
$handoff = Join-Path $env:RELAYCORE_ROOT ".RelayCore\.agent-tasks\$taskId\HANDOFF.md"
$candidate = Join-Path $env:RELAYCORE_ROOT ".RelayCore\workspaces\$taskId\message.txt"
Get-Content -LiteralPath $handoff
Get-Content -LiteralPath $candidate
Get-Content -LiteralPath (Join-Path $env:RELAYCORE_ROOT 'message.txt')
```

检查交接中的 `Snapshot ID`、审查结果与候选内容；源文件此时应仍为 `pending`。若结果不符合预期，保留现场并停止，不要整合。

仅在确认要把**这个测试候选**写入**这个测试项目**时，将下面的 `替换为HANDOFF中的完整Snapshot-ID` 换成交接里的完整 ID：

```powershell
$snapshotId = '替换为HANDOFF中的完整Snapshot-ID'
node .\src\control.mjs integrate $taskId $snapshotId
Get-Content -LiteralPath (Join-Path $env:RELAYCORE_ROOT 'message.txt')
```

预期源文件变为 `ready`。程序在写入前保存备份；若源文件已变化或快照不匹配，整合会拒绝。若要在**没有再修改源文件**的前提下恢复本次测试：

```powershell
node .\src\control.mjs rollback $taskId
Get-Content -LiteralPath (Join-Path $env:RELAYCORE_ROOT 'message.txt')
```

预期恢复为 `pending`。回滚是一次性的；整合后若你又修改了源文件，回滚会拒绝覆盖。多文件写入或回滚中途发生故障时，仍需人工检查源文件与 `RECOVERY_REQUIRED` 状态，不能假定文件系统和数据库是一项原子事务。

## 8. 如何停止、保留和排查

- 只停止你确认属于本次测试的 Daemon；先检查任务状态，再回到其启动窗口按 `Ctrl+C`。关闭网页不会停止任务，也不保证远端模型立即停止。
- 如果 Daemon 因异常退出留下锁，先核对对应项目、进程和任务状态；不要只因为端口无响应就删锁。需要删除或清理现场前，先确认不丢失未提交代码、任务、笔记和证据。
- 测试结束后可以保留 `RelayCore-tryout` 以便学习。`local/` 与 `.RelayCore/` 都不进入 Git；备份前先停止该项目写入，注意 SQLite WAL 一致性，并检查会话、令牌和登录资料是否需要脱敏。
- 如果单独创建的 `relaycore-tryout` MCP 连接不再需要，可在确认没有任务依赖它后由你运行 `codex mcp remove relaycore-tryout`。这是修改用户配置；不要误删原有 `relaycore` 连接。
- 排查优先看任务状态/事件和测试项目的现场。若要分享日志，先去掉凭据、会话、项目内容和其他敏感信息。

## 9. 下一步验收什么？

无模型测试通过只能证明测试覆盖到的行为。要更接近日常使用，仍需要：

1. 在安全的隔离环境逐项核实 Phase 0 的 Windows 权限、网络和子进程边界。
2. 验证真实模型在途暂停后，同一次任务能完成审查、整合和回滚；记录失败与费用，避免把不同现场拼成一次成功。
3. 核对真实用量记录与服务端账单口径，并评估长期稳定性、并发文件变更和故障恢复。
4. 确认备份恢复、操作台信任边界和发布材料；完成前不将本项目视为生产就绪产品。

详细状态见 [Phase 0 可行性记录](phase-0-feasibility.md)、[Phase 3 状态](phase-3-status.md)、[Phase 5 状态](phase-5-status.md) 和仓库根目录的 [安全说明](../SECURITY.md)。
