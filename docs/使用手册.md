# RelayCore 使用手册

更新：2026-11-08。适用对象：在本机运行 RelayCore 的操作者。原则：**真正的操作发生在 Codex 聊天（派发）与 DSH（看执行记录）里，控制台只承担用量分账与授权认证**。

## 1. 首次安装（一次性）

前提：Windows + Node.js ≥24.15.0 <25、git、已安装 DeepSeek Harness 桌面版。`node src/doctor.mjs` 可逐项自检。

1. `npm install`
2. `npm start` —— 终端打印一条**控制台配对链接**（10 分钟内有效、一次性）；`RELAYCORE_OPEN=1` 时自动打开浏览器
3. 通过配对链接登录控制台，在"首次设置"表单填写 **DSH 可执行文件路径**与 **DSH 账户工作区**，点"保存连接配置"（写入 `.RelayCore/bridge/config.json`，不含任何密钥）
4. `Ctrl+C` 停止后重新 `npm start` —— Daemon 以执行模式启动，控制台顶部显示"执行状态：已启用"
5. Codex Desktop 的 `~/.codex/config.toml` 登记 relaycore MCP（详见 [Codex MCP 接入](codex-mcp-manual-setup.md)）

## 2. 日常使用（每天的实际工作流）

### 2.1 启动

在项目目录 `npm start`，保持终端开着；`Ctrl+C` 停止。执行未启用时控制台顶部会提示先完成首次设置。

### 2.2 在 Codex 聊天里派发任务

对 Codex 说话即可，它会调用 MCP 工具：

| 你说的话 | Codex 实际调用 |
|---|---|
| "创建一个任务：把 message.txt 改成 ready，验收是精确匹配" | `create_task` |
| "派发这个任务" | `dispatch_task`（需先在控制台授权） |
| "任务进行得怎么样" | `task_status` / `task_events` |
| "暂停一下，追加引导：不要动其他文件" | `pause_task` + `guide_task` |
| "恢复" | `resume_task` |
| "停下来" | `stop_task` |
| "看看所有任务" | `list_tasks` |

派发后链路自动走完：**DSH 账户执行（只读沙箱提出修改提案）→ Codex 独立审查 → 等待你整合**。

### 2.3 授权与整合（控制台）

任务创建后到控制台（`127.0.0.1:8765/ui`）操作：

- **授权**：勾选"同意未知费用"（必勾）——这是金额无法硬封顶情况下的显式确认；E2 高危任务另需勾选"E2 L3 同意"。点"确认授权"后才能派发
- **整合**：任务 COMPLETED 后点"整合"，自动使用最新审查快照写入你的真实工作区；出问题点"回滚"还原
- **追加引导**：任务列表"引导"列输入文字点"引导"，内容折入下一次真实模型回合

### 2.4 在 DSH 里看执行记录

派发产生的每个 DSH 会话**自动登记**进 DSH 工作区注册表：打开 DSH Desktop/Web，左侧栏对应工作区下出现 `【任务标题】` 开头的会话，点开即原生界面查看完整对话（含思考过程）。注意：不要在 DSH 界面里重命名/隐藏工作区会话——DSH 的注册表以内存为准，会覆盖外部登记（下次派发自动补挂）。

### 2.5 看用量

控制台"用量分账"页（或 `/usage`）：DSH 按会话上下文占用、Codex 按输入/输出 tokens 分列。上下文占用不等于费用，实际费用以服务端账单为准。

## 3. 任务状态参考

| 状态 | 含义 | 你的动作 |
|---|---|---|
| DRAFT | 草稿，可改执行上限（保存会生成新草稿） | 授权 |
| QUEUED / RUNNING | 排队/执行中 | 等待；可暂停/停止/引导 |
| PAUSED | 已暂停（可恢复，重放幂等） | 恢复或停止 |
| RECOVERY_REQUIRED | 在途取消/崩溃/审查额度尽 | 查看事件定位原因后停止或恢复 |
| COMPLETED | 审查通过，等整合 | 控制台"整合"；不满意可"回滚" |
| CANCELED | 已取消（本地终态，远端不保证立即停） | 无 |

## 4. 命令速查

| 命令 | 用途 |
|---|---|
| `npm start` | 启动 Daemon（默认关闭执行，配置后启用） |
| `npm test` | 全量回归（当前 156 项） |
| `npm run check:dispatch` / `check:review` / `check:dsh-account` | 对应链路的零模型健康检查（自带 `--check-only`） |
| `npm run smoke:tasks` | 无模型任务生命周期冒烟 |
| `npm run diagnose:crash` | 崩溃恢复诊断 |
| `npm run login:review` | 刷新 Codex 审查登录 |
| `node src/control.mjs ui-session` | 配对链接过期时手动获取一次性登录令牌 |
| `node src/doctor.mjs` | 环境自检 |

## 5. 故障排查

- **派发报"external execution disabled"**：没保存连接配置或没重启——回第 1 节第 3-4 步
- **端口 8765 被占**：换 `RELAYCORE_PORT` 环境变量
- **报 daemon.lock 已存在**：先确认没有 Daemon 进程（任务管理器查 node），再手动删除 `.RelayCore/bridge/daemon.lock`
- **DSH 升级后链路异常**：跑 `npm run check:dsh-account`（零花费）；CLI 路径变化时适配 `dshAcpArgs()`，不要改 DSH 安装包
- **MCP 注册消失**：`codex mcp list` 核对登记；必要时重启 Codex Desktop（见 MCP 接入文档）

## 6. 安全边界摘要

- 控制台绑定本机回环 + 一次性配对 + 8 小时会话 cookie；跨站请求结构性拒绝；能访问本机端口的进程仍属同一信任级别
- DSH 执行是只读沙箱：提案只写候选副本，Codex 独立审查、你批准后才写入真实工作区，可回滚
- "同意未知费用"是金额硬上限缺失时的替代确认；**模型回合上限不等于金额上限**
- 完整 Windows 隔离、金额硬封顶、长期稳定性仍未验证——**不建议处理重要项目或生产数据**

完整威胁模型见 [SECURITY.md](../SECURITY.md)；架构与验收历史见 [dsh-integration](dsh-integration.md)、[Codex 审查](codex-review.md) 与阶段状态文档。
