# RelayCore 使用手册

更新：2026-11-08。面向在 Windows 本机部署和使用 RelayCore 的用户（开源后包括非开发者本人）。

RelayCore 的分工：**Codex 负责规划和验收（在它的聊天里派发任务），DSH 负责执行（会话记录出现在 DSH 自己的界面里），本地网页控制台只承担用量分账与授权审批**。

## 1. 前提条件

- Windows 10/11，Node.js ≥24.15.0 <25（`node --version` 确认），git
- [DeepSeek Harness（DSH）桌面版](https://github.com/deepseek-ai/deepseek-harness)已安装，并**登录过 DSH 账户**（账户模式不使用 API Key）
- 一个可用的 Codex 桌面版账号（用于规划和独立审查）
- 项目将部署在你指定的**任意一个普通文件夹**（下称"项目根"），它就是 DSH 侧的工作目录，也是 RelayCore 保存任务数据的根

## 2. 部署（一次性）

```powershell
git clone https://github.com/learnerCodeZ/RelayCore.git
cd RelayCore
npm install
```

然后在项目根运行：

```powershell
npm start
```

首次启动会打印一条**控制台配对链接**（10 分钟内有效、一次性）；设 `RELAYCORE_OPEN=1` 可自动打开浏览器。

### 2.1 控制台首次设置

1. 点击配对链接进入控制台（`http://127.0.0.1:8765/ui`）
2. 顶部"首次设置"表单填写两项：
   - **DSH 可执行文件路径**：如 `C:\Users\<你>\AppData\Local\Programs\deepseek-harness\DeepSeek Harness.exe`（以本机实际安装位置为准）
   - **DSH 账户工作区**：你想让 DSH 干活的那个文件夹的完整路径（同一台机器上 DSH 桌面版添加过的工作区目录即可）
3. 点"保存连接配置"——写入 `<项目根>\.RelayCore\bridge\config.json`，不含任何密钥
4. `Ctrl+C` 停止后重新 `npm start`，控制台顶部应显示"执行状态：已启用"

### 2.2 初始化 Codex 审查登录

真实派发前运行一次：

```powershell
npm run login:review
```

按提示完成 Codex 登录。独立审查通道复用这个专用登录目录（位于 RelayCore 安装目录下，不在你的项目里）；额度尽时任务会如实转入 `RECOVERY_REQUIRED`。

### 2.3 把 MCP 登记进 Codex

按 [Codex MCP 接入](codex-mcp-manual-setup.md)操作：在 `~/.codex/config.toml` 添加 relaycore 服务项（command/args/cwd 指向你的 RelayCore 安装目录），九个任务工具即可在 Codex 聊天里使用。口令为 DPAPI 加密自动生成，无需手动管理。

## 3. 日常使用

### 3.1 启动与停止

```powershell
npm start    # 保持终端开着；Ctrl+C 停止
```

### 3.2 在 Codex 聊天里派发任务

对 Codex 说话即可，它会调用 MCP 工具：

| 你说的话 | Codex 实际调用 |
|---|---|
| "创建一个任务：把 message.txt 改成 ready，验收是精确匹配" | `create_task` |
| "派发这个任务" | `dispatch_task`（需先在控制台授权） |
| "任务进行得怎么样" | `task_status` / `task_events` |
| "暂停一下，追加引导：不要动其他文件" | `pause_task` + `guide_task` |
| "恢复" | `resume_task` |
| "停下来" | `stop_task` |
| "看看所有任务" | `list_tasks` |

派发后链路自动走完：**DSH 账户执行（只读沙箱提出修改提案）→ Codex 独立审查 → 等待你在控制台整合**。

#### 让 GPT 自动掌握派发节奏（一次性配置）

把下面这段粘贴进 Codex 的 AGENTS.md（或每次对话开头），GPT 就会按固定节奏协作，不用每轮重复交代：

```markdown
## RelayCore 任务派发节奏

1. 用户描述了明确可执行的需求 → 立即用 relaycore 的 create_task 建草稿：
   - title 简短可读（它会成为 DSH 侧栏的会话标题）
   - objective/acceptance 写清目标和可核对的验收标准
   - 需要给执行方更具体的执行指令时，用 prompt 字段直接写给 DSH
     （自由文本，最长 8000 字符；RelayCore 会自动附加只读安全框架和
     JSON 输出契约，所以 prompt 里不必重复这些）
   - allowedPaths 只列任务真正需要改的文件
2. 建好草稿后回复："任务 <ID> 已创建，请到控制台授权（http://127.0.0.1:8765/ui）"
3. 用户说"已授权" → 用 task_status 确认授权状态存在，立即 dispatch_task
4. 运行期间用户要求调整 → pause_task / guide_task / resume_task；用户说"停" → stop_task
5. 任务 COMPLETED → 提醒用户到控制台点"整合"；不要尝试自己写用户的源文件
6. 任何工具失败（含派发被拒）→ 如实报告错误原文，不要重试绕过授权
```

说明：`prompt` 字段就是"GPT 给 DSH 写提示词"的通道——GPT 自写的指令会出现在 DSH 收到提示词的最前面（任务标题之后、固定契约之前），DSH 侧栏标题与执行指令都随任务走。授权与整合永远无法被 GPT 代替，这是金额安全的根基。

### 3.3 授权与整合（控制台）

- **授权**：任务创建后，控制台任务列表展开"授权"，勾选"同意未知费用"（必勾）；E2 高危任务另需勾选"E2 L3 同意"，点"确认授权"
- **整合**：任务 COMPLETED 后点"整合"，自动使用最新审查快照写入你的项目根；出问题点"回滚"还原
- **执行上限**：DRAFT 任务可展开"执行上限…"调整秒数/轮数（保存会生成新草稿）

### 3.4 在 DSH 里看执行记录

派发产生的每个 DSH 会话**自动登记**进 DSH 工作区注册表：打开 DSH，左侧栏对应工作区下出现 `【任务标题】` 开头的会话，点开即原生界面查看完整对话（含思考过程）。默认开启；在 `config.json` 加 `"dshRegistryAttach": false` 可关闭（关闭后仅在控制台查看）。注意：**不要在 DSH 界面里重命名/隐藏工作区会话**——DSH 的注册表以内存为准，可能覆盖外部登记（下次派发自动补挂）。

### 3.5 看用量

控制台"用量分账"页：DSH 按会话上下文占用、Codex 按输入/输出 tokens 分列。上下文占用不等于费用，实际费用以服务端账单为准。

## 4. 任务状态参考

| 状态 | 含义 | 你的动作 |
|---|---|---|
| DRAFT | 草稿，可改执行上限（保存会生成新草稿） | 授权 |
| QUEUED / RUNNING | 排队/执行中 | 等待；可暂停/停止/引导 |
| PAUSED | 已暂停（可恢复，重放幂等） | 恢复或停止 |
| RECOVERY_REQUIRED | 在途取消/崩溃/审查额度尽/整合回滚中断 | 查看事件定位原因后停止或恢复 |
| COMPLETED | 审查通过，**待整合**（源文件尚未修改） | 控制台"整合"；不满意可"回滚" |
| CANCELED | 已取消（本地终态，远端不保证立即停） | 无 |

## 5. 命令速查

| 命令 | 用途 |
|---|---|
| `npm start` | 启动 Daemon（默认关闭执行，配置后启用） |
| `npm test` | 全量回归（当前 164 项） |
| `npm run check:dispatch` / `check:review` / `check:dsh-account` | 对应链路的零模型健康检查（自带 `--check-only`） |
| `npm run smoke:tasks` | 无模型任务生命周期冒烟 |
| `npm run diagnose:crash` | 崩溃恢复诊断 |
| `npm run login:review` | 刷新 Codex 审查登录 |
| `node src/control.mjs ui-session` | 配对链接过期时手动获取一次性登录令牌 |
| `node src/doctor.mjs` | 环境自检 |

环境变量：`RELAYCORE_ROOT`（项目根，默认当前目录）、`RELAYCORE_PORT`（默认 8765）、`RELAYCORE_OPEN=1`（自动开浏览器）、`RELAYCORE_MAX_DURATION`/`RELAYCORE_MAX_TURNS`、`RELAYCORE_EXECUTION`（`account` 强制启用 / `off` 等强制关闭，优先于 config.json）、`RELAYCORE_DSH_EXE`/`RELAYCORE_ACCOUNT_WORKSPACE`。

## 6. 故障排查

- **派发报"external execution disabled"**：没保存连接配置或没重启——回第 2.1 节
- **端口 8765 被占**：换 `RELAYCORE_PORT`
- **报 daemon.lock 已存在**：先确认没有 Daemon 进程（任务管理器查 node），再手动删除 `<项目根>\.RelayCore\bridge\daemon.lock`
- **DSH 升级后链路异常**：跑 `npm run check:dsh-account`（零花费）；CLI 路径变化时适配 `dshAcpArgs()`，不要改 DSH 安装包
- **MCP 注册消失**：`codex mcp list` 核对；必要时重启 Codex Desktop
- **恢复失败/状态异常**：见第 4 节 RECOVERY_REQUIRED 行；整合/回滚中断的场景启动时会自动对账并给出明确状态

## 7. 安全边界摘要

- 控制台绑定本机回环 + 一次性配对 + 8 小时会话 cookie；跨站请求结构性拒绝；**能访问本机端口的进程仍属同一信任级别**
- DSH 执行是只读沙箱：提案只写候选副本，Codex 独立审查、你批准整合后才写入真实项目，可回滚
- "同意未知费用"是金额硬上限缺失时的替代确认；**模型回合上限不等于金额上限**；取消不保证远端立即停止计费
- 完整 Windows 隔离、金额硬封顶、长期稳定性仍未验证——**不建议处理重要项目或生产数据**

完整威胁模型见 [SECURITY.md](../SECURITY.md)；设计与验收历史见 [dsh-integration](dsh-integration.md)、[Codex 审查](codex-review.md) 与阶段状态文档。
